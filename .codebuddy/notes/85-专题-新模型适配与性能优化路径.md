# 专题：新模型适配与性能优化路径

> 依据：`docs/user-guide/parallelism-guide.md`（选型指南 `:147-253`）

## Part 1：适配新模型——按改动量分四层

### Level 0：只改配置（LLaMA/Mistral/Qwen 类参数变体）

GQA / SwiGLU / RoPE / RMSNorm 均可命令行表达（`--num-query-groups`、`--gated-linear-unit`、`--normalization RMSNorm` 等），参照 `examples/llama/train_llama3_8b_h100_fp8.sh`。

### Level 1：换 layer spec（新算子组合，不动 core）

重新组合现有积木，写一个 spec 工厂文件。参照 `gpt_layer_specs.py:179`（TE 版）/ `:359`（local 版）、`moe_module_specs.py`。

### Level 2：新模型类（新架构）

固定模式 = **4 文件 + 1 组测试**：

```
megatron/core/models/<name>/
  ├── <name>_model.py          # 模型类
  └── <name>_layer_specs.py    # spec 工厂
根目录/
  ├── <name>_builders.py       # builder
  └── pretrain_<name>.py       # 训练入口
tests/unit_tests/models/test_<name>_model.py
tools/checkpoint/              # （可选）HF 权重转换
```

模型类三契约（参照 `gpt_model.py:52`）：

| 契约 | 参照 | 作用 |
|---|---|---|
| `__init__(config, pre_process, post_process, ...)` | `:98` | PP 感知：仅 `pre_process` 建 embedding、仅 `post_process` 建 output layer |
| `set_input_tensor` | `:311` | PP 胶水 |
| `sharded_state_dict` | `:932` | 分布式 checkpoint |

骨架照抄 `GPTModel` 三段式（`_preprocess` → `decoder` → `_postprocess`）。能复用 `TransformerBlock` 就复用，工作只剩写层和写 spec。

`pretrain_<name>.py` 抄 `pretrain_gpt.py`，只改 4 处：`forward_step:295`、`loss_func:222`、`get_batch:110`、`datasets_provider:458`。

**适配顺序**：单 GPU + mock data 跑通 → 与参考实现逐 logits 对齐（小配置）→ TP=2 / PP=2 依次跑通 → golden values 测试固化 → 才开始性能优化。

### Level 3：新 layer 类型（Mamba/SSM 类全新算子）

Level 2 + 自定义层 + `hybrid_layer_pattern` 插进层序列。参照 `core/ssm/` + `models/hybrid/hybrid_layer_specs.py` + `pretrain_hybrid.py`。

## Part 2：性能优化顺序

官方原则（`parallelism-guide.md:237-241`）：DP 起步 → 放不下加 TP → 超大模型加 PP → 长序列加 CP。

### 阶段 0：单卡基线

mock data 跑通，记录 loss 曲线、iter 时间、MFU（`training.py:802` 是 FLOPs 模型）。**没有基线无法证明任何优化有效。**

### 阶段 1：单卡效率

| 优先级 | 优化 |
|---|---|
| 1 | `--bf16` |
| 2 | `--transformer-impl transformer_engine`（fused softmax/LN/RoPE，见笔记 75） |
| 3 | `--recompute-granularity selective`（不够再 `full`） |
| 4 | `--gradient-accumulation-fusion` |

### 阶段 2：并行扩展

```
DP（填满剩余 GPU）
  ↑ 放不下？ TP ≤8（限单节点 NVLink 域，见笔记 20 order 语义）
  ↑ 单节点放不下？ PP（1F1B；bubble 大上 VPP）
  ↑ 序列太长？ CP
  ↑ MoE？ EP
```

官方推荐配置（`parallelism-guide.md:155-170`）：

| 模型 | GPU | TP | PP | CP | EP |
|---|---|---|---|---|---|
| LLaMA-3 8B | 8 | 1 | 1 | 2 | 1 |
| LLaMA-3 70B | 64 | 4 | 4 | 2 | 1 |
| LLaMA-3.1 405B | 1024 | 8 | 8 | 2 | 1 |
| DeepSeek-V3 | 1024 | 2 | 16 | 1 | 64 |

microbatch：`num_microbatches ≥ 4 × pp_size`（bubble ≈ (p-1)/(n+p-1)）。

### 阶段 3：通信三件套

```bash
--sequence-parallel                  # 用 TP 就开（指南 :225-227）
--use-distributed-optimizer          # 多卡必开（:211-217）
--overlap-grad-reduce --overlap-param-gather
# 进阶：--tp-comm-overlap --overlap-p2p-communication --overlap-moe-expert-parallel-comm
```

原理对应：SP（笔记 40 A3）、DistOpt（笔记 50 §7）、桶级 hook（笔记 50 §3）。

### 阶段 4：内核级（最后做）

FP8（H100+）→ 融合核（`--bias-dropout-fusion --masked-softmax-fusion`）→ 序列打包（变长场景）→ CUDA Graph（实验性）。

### 阶段 5：profiling 闭环

`--timers` + TensorBoard（`training.py:3280`）、`StragglerDetector`、OTel span。每 GPU 时间 = 计算 + 通信 + bubble，三路归因。

### 铁律

1. 每次只开一个优化，对照基线验证 loss 曲线不变
2. TP 不跨节点；跨节点交给 PP/DP
3. golden values 测试是每次优化的回归门
4. 显存不够先分清"激活还是权重"：权重/优化器状态 → TP/DistOpt/FSDP；激活 → 重计算/SP/CP
